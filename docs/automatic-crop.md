# Automatic crop trial in the browser extension

The owner authorized integration after the standalone feasibility tool. The browser preview now starts Gemini detection after the recording/upload consent notice. No credentials are stored in extension files: the native host reads a CurrentUser-DPAPI-encrypted Gemini key from local app settings. Model remains pinned to `gemini-3.8-flash`, rather than the moving `gemini-flash-latest` alias. Medium image resolution and LOW thinking are used. No billing is enabled or changed; ensure the key's Google project remains on Free tier. The API key alone does not let the app verify billing status.

## Try it

1. Finish any current recording. Open `chrome://extensions` and reload LectureLens (the updated build is in `dist/extension`).
2. Open a lesson tab, accept the updated recording/image-upload notice and choose Preview.
3. A box appears when detection succeeds. Start is disabled until a valid automatic box is applied, or you explicitly save a manual selection (including Full frame). An in-progress request is never presented as a confirmed crop. Manual “Choose slide area” locks your chosen box and stops cloud detection. “Retry automatic crop” enables it again during preview. A stale response changes the status to scene-changed rather than leaving it stuck on detecting.
4. Once per second, a local 160×90 grayscale comparison checks for meaningful visual change. After a successful detection, only blocks inside the last detected region are compared, so sidebar/chat updates are ignored. More than 12% of those blocks must change to request reanalysis; small cursor movements are ignored. A new scene must settle for two seconds (no more than 2.5% block changes) before upload. The last successful crop remains active while re-detection is pending. A page change does not discard its known location. Requests run at most once per minute and at most 10 per automatic-detection activation; identical stable scenes, including scenes classified as non-educational, need no further request. Quota/authentication failures disable further requests for that activation.
5. Review saved slides: verify no text is cut off, whether moved/resized content is found, and whether unnecessary UI is included. Check that audio continues during detection and when the network is unavailable.

## Reliability and limitations

Vision uses a separate native host connection; requests never enter the audio persistence queue. Responses are applied only while the detector is active and the scene remains similar. No model-generated image is used: normalized coordinates are used without added padding and the existing canvas crops locally from the full-resolution captured frame. The full-frame JPEG sent to Gemini is quality-bounded to fit native messaging; extremely large frames fall back safely. Invalid or missing regions, network errors and the request cap retain the last successful crop and mark it for review. Full-frame fallback applies only when no successful crop exists yet.

Scene-change detection is approximate: a sufficiently small movement or subtle change can evade it. This is an experimental crop aid, not verified exact localization. If the teacher moves/resizes the shared content, the old box may be inaccurate until a valid new detection arrives. At the request cap or after a disabling failure, it remains the last known box; inspect those review-marked captures. Paused sessions make no new detection requests, but a request already sent may finish. The manual crop remains available in preview. Closing/reloading the extension during capture still ends its stream; reload only after recording finishes.

Actual response usage and normalized detections are stored under `%LOCALAPPDATA%/LectureLens/vision-cache`; no key is included. Cache keys cover image bytes, model, prompt and settings. `.usage.json` records actual usage, including failed model-output validation; cache reuse makes no request. Recording visual-event logs distinguish Gemini detection, scene changes, failure and cap; the logged crop records the box actually used. Private screenshot cache files and keys are outside the repository.

Verified offline: native request/config, margin, cache, usage and quota handling; extension stale-response rejection, no-repeat behavior, manual override, independent persistence while vision hangs, and normal durability tests. No real lesson or model call was run by the agent. Detection accuracy and account/model access need the owner's live check.

## Regression check (2026-10-24)

Offline replay simulates ten minutes, three distinct slides, changing sidebar text, a delayed second response and a quota failure: exactly three cropped slides are saved. Separate checks cover valid relocation, empty/invalid replies, stale responses and manual override. For a real-browser check, record three pages with changing chat, end/save, then inspect Review slides and a newly generated PDF for exactly the intended cropped content. Existing saved images/PDFs are not recropped by this fix.

Transient HTTP 408/500/502/503/504 errors and transport timeouts now allow up to three automatic retries, waiting about 60, 120 and 240 seconds plus jitter after the failure. Retries count toward the existing ten-request cap, use the latest settled frame, and retain the last detected crop. Authentication/quota failures still stop requests. Offline checks cover 503 classification, recovery, backoff and exhaustion; service availability itself is not verified by mocks.

## Resize/movement tracking (2026-10-24)

Between cloud responses the sampler follows nearby rectangular slide edges at 640px analysis width. Candidates must have strong edge support, similar aspect ratio and plausible size/position relative to the last box; manual crops are unchanged. The original-resolution image is cropped to that rectangle before normalization and deduplication. No artificial margin is added in either the native adapter or standalone experiment. A synthetic replay verifies one page shrinking and moving produces one saved slide, while an actual content change produces a second. Ambiguous/low-contrast boundaries retain the last box pending cloud detection; large layout changes still need Gemini or manual selection. Existing saved images are not rewritten.
